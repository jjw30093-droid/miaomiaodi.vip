# 本地数据湖全量技术百科 (Football Data Lake Encyclopedia)

这份文档旨在为 Master Analyst AI 提供数据湖的“单一真理来源”。它涵盖了所有 SQLite 表、字段定义、业务逻辑以及 JSON 配置文件结构。

---

## 🏗 数据分层架构 (Architecture)

1.  **Dim Layer (维度层)**: 核心实体元数据（比赛、球员、球队映射）。
2.  **Fact Layer (事实层)**: 原始采集的逐场比赛/球员统计、赔率数据。
3.  **Intelligence Layer (智能特征层)**: 经过特征工程生成的滚动指标（PPDA, npxGD 等）。
4.  **Mart Layer (集市层)**: 最终用于前端展示和决策生成的聚合矩阵。
5.  **Multimodal Layer (多模态存储)**: 存储 Markdown 研报、趋势图 JSON、射门图数据。

---

## 🌐 Domain 1: 核心基础维度 (Core Dimensions)

### 1.1 `dim_match` (比赛维度表)
记录比赛的核心基础信息，是所有事实表的关联基础。

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `match_id` | TEXT | FotMob 比赛 ID (Primary Key) |
| `home_id` | INT | 主队 ID |
| `away_id` | INT | 客队 ID |
| `league_id` | INT | 联赛 ID |
| `match_time` | TEXT | 比赛开始时间 (UTC) |
| `status` | TEXT | 比赛状态 (Finish, Upcoming) |
| `home_score` | INT | 主队得分 |
| `away_score` | INT | 客队得分 |

### 1.2 `dim_player` (球员维度表)
记录球员的静态属性。

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `player_id` | TEXT | 球员唯一 ID |
| `player_name` | TEXT | 球员姓名 |
| `team_id` | INT | 所属球队 ID |
| `position` | TEXT | 场上位置 |
| `market_value` | TEXT | 市场价值 (字符串形式) |

### 1.3 `team_mapping` (球队实体映射)
用于解决不同数据源（FotMob, Football-Data.co.uk）之间球队名称不一致的问题。

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `fotmob_name` | TEXT | FotMob 侧的球队名称 |
| `fd_name` | TEXT | Football-Data.co.uk 侧的名称 |
| `standard_name` | TEXT | 归一化的标准名称 |

## 📥 Domain 2: 数据事实层 (Fact Layer - Ingestion)

这一层记录了从 FotMob 等外部 API 采集的逐场比赛原始统计数据。

### 2.1 `fact_team_match_stats` (球队比赛事实表)
记录每场比赛中两支球队的详细统计指标。相关字段包括：
- `expected_goals` (xG), `expected_goals_conceded` (xGA)
- `possession` (控球率), `field_tilt` (前场压制)
- `ppda` (高位逼抢强度)
- `big_chances_created` (创造绝佳机会)

### 2.2 `fact_player_match_stats` (球员比赛事实表)
记录每位球员单场表现。核心字段：
- `minutes_played`, `goals`, `assists`, `rating` (FotMob 评分)
- `expected_goals` (球员 xG), `expected_assists` (球员 xA)

## 🧠 Domain 3: 深度特征层 (Intelligence Layer)

这是数据湖的核心竞争力，通过特征工程（Rolling Window）生成的深度指标。

### 3.1 `int_team_rolling_features` (球队滚动特征表)
通常使用最近 5 场比赛的移动平均值（Roll 5）。

| 特征字段 | 业务含义 |
| :--- | :--- |
| `roll_5_npxGD` | 近5场非点球预期净胜球 (反映真实统治力) |
| `roll_5_ppda` | 近5场逼抢强度均值 |
| `roll_5_field_tilt` | 近5场前场控球占比 |
| `roll_5_golden_zone_ratio` | 黄金区域（禁区内高价值区）射门比例 |
| `roll_5_box_shot_ratio` | 禁区内射门比例 |
| `roll_5_shot_quality_added` | 射门质量溢价 (xG vs xGOT) |

### 3.2 `int_player_influence` (球员影响力)
衡量球员对球队数据的贡献占比。

---

## 📊 Domain 4: 结果与预测层 (Analytical Marts)

### 4.1 `int_team_match_flattened` (展平比赛特征表)
将主客队的数据在单行内对齐，用于直接对比分析。

- **核心字段**: `npxGD`, `xGD`, `big_chances_diff`, `possession_diff`, `field_tilt` 等。
- **用途**: AI 模型评估比赛实力的基础输入。

---

## 📂 Domain 5: 多模态存储与报表 (Multi-modal Space)

这一层存储最终交付给用户（或前端）的非结构化/半结构化数据。

### 5.1 `report_store` (研报元数据表)
用于管理前端显示的研报列表索引。

- `id`: 自增 ID
- `match_id`: 关联比赛
- `title`: 研报标题 (e.g., "Arsenal vs Man City 深度研报")
- `status`: 研报状态 (HOT, VIP, FREE)
- `category`: 联赛分类

### 5.2 `match_payloads` (内容负载表)
存储研报的实际内容和动态图表所需的 JSON 数据。

| 字段名 | 类型 | 说明 |
| :--- | :--- | :--- |
| `report_markdown` | TEXT | 完整的 AI 生成 Markdown 文本 |
| `npxg_trend` | TEXT (JSON) | 比赛过程中的 xG 累积趋势数据数组 |
| `shot_map_data` | TEXT (JSON) | 格式化的射门图数据，前端渲染必备 |

## ⚙️ Configuration: 关键配置文件 (JSON Schemas)

### 1. `team_mapping.json` (球队映射字典)
用于解决 API 间命名差异。
```json
{
  "Team Name in DB": {
    "fotmob": "Arsenal",
    "opta": "Arsenal FC",
    "fbref": "Arsenal CC"
  }
}
```

### 2. `target_matches.json` (目标比赛计划)
驱动爬虫和报表生成的调度配置。
```json
[
  {
    "match_id": "1234567",
    "league": "Premier League",
    "time": "2026-04-04 15:00:00"
  }
]
```

## 🛠 ETL 流程说明 (Pipeline Logic)

1.  **Ingestion**: `postmatch_scraper.py` 从 API 抓取原始 JSON 存入 `fact_` 表。
2.  **Intelligence**: `int_team_rolling_features` 通过 SQL Window Function 计算最近 5 场移动平均。
3.  **Synthesis**: `generate_report.py` 调用 Gemini 3 Pro，结合 Intelligence Layer 字段生成 Markdown。
4.  **Distribution**: 研报和 Payloads 被存入 `report_store` 和 `match_payloads`，通过 `api_server.py` 暴露给前端。
